## 概要

自宅で淹れたコーヒーや作ったお菓子を、ただの写真フォルダではなく **「自分のカフェのメニュー表」** として残せたら楽しいのでは、という発想から作った Web アプリです。

登録したメニューは黒板メニュー風・紙の冊子風のレイアウトで表示され、公開設定をオンにすると `/u/[ユーザー名]` の公開ページとして誰でも閲覧できます。

**公開中** → [https://mon-cafe-myhero.vercel.app](https://mon-cafe-myhero.vercel.app)

**リポジトリ** → [github.com/Myhero2003/MonCafe_myhero](https://github.com/Myhero2003/MonCafe_myhero)

## 技術構成

| 技術 | 用途 |
|------|------|
| **Next.js (App Router)** | ルーティング・Server Component でのデータ取得 |
| **TypeScript** | 型定義（メニュー・プロフィールの構造化） |
| **Supabase** | 認証 / Postgres / Storage / Row Level Security |
| **Tailwind CSS** | スタイリング・デザイントークンの集約 |
| **Vercel** | ホスティング・デプロイ |

## 主な機能

- **メニュー登録**: 商品名・カテゴリ（ドリンク / フード / スイーツ）・値段風の表記・星評価・メモ・画像を登録
- **2つの表示モード**: カテゴリ別のカードが並ぶ**スクロール表示**と、ページをめくる**冊子表示**を切り替え可能
- **本日のおすすめ**: 登録メニューからランダムに1件を提案。同じものが連続しないよう再抽選するボタンつき
- **公開 / 非公開の制御**: カフェ単位・商品単位の2段階で切り替え。公開URLのコピーにも対応
- **OGP画像の動的生成**: 公開ページごとに、カフェ名入りのOGP画像を自動生成

## 工夫した点

### 公開判定をデータベース側に置く

「非公開のメニューは、そもそもクライアントから取得できない」状態にしたかったため、公開・非公開の判定を画面側の分岐ではなく **Supabase の Row Level Security ポリシー**として書きました。

`profiles.is_public` と `menu_items.is_public` の両方を見るポリシーにすることで、「カフェごと非公開」「特定の商品だけ非公開」の2段階を、UI のコードを増やさずに表現しています。ブラウザに露出するキーは publishable キーのみとし、RLS をバイパスする `service_role` キーはアプリ側で一切使わない構成にしました。

### 紙のメニュー帳らしさをどう出すか

冊子表示では、罫線の背景・紙が重なった影・めくりアニメーションを組み合わせて、実際のメニュー帳をめくる感覚に近づけました。1ページあたりの掲載数を固定してページ単位に分割し、めくる方向によってアニメーションを出し分けています。

### 取得と操作の分離

一覧の取得は Server Component、追加・削除・公開切り替えなどの操作はクライアント側のコンポーネントに寄せました。初期表示はサーバー側で完結させつつ、操作の反応は即座に返るようにしています。

## デザインの方針

**黒板メニュー × フレンチビストロ**をテーマに、ブラウン / ゴールドの暖色系で統一しました。見出しは Playfair Display（欧文セリフ）と Klee One（手書き風）、本文は Noto Sans JP を使い分けています。配色とフォントは Tailwind の設定とグローバル CSS に集約し、画面ごとに色を書き足さなくて済むようにしました。
